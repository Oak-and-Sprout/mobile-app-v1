Nursery Mode — Overhaul PRD

Product: Sprout Track (PWA)  ·  Feature: Nursery Mode redesign — scenes, quick logging & personalization  ·  Version: 1.0 Draft  ·  Date: Jul 13, 2026  ·  Owner: John Overton

Prototype: nursery-mode.html (interactive; all scenes, settings & controls functional)

1. Overview

Nursery Mode today is a static dimmed clock over a single "lava lamp" gradient. This overhaul turns it into a stylish, personalizable nightlight + care station: a large serif clock and baby name over one of four configurable scenes, with activity cards or big tile icons for one-tap logging of Feed, Pump, Diaper, and Sleep. Every visual element — scene, background pattern, palette, icon shape and color, button transparency, dimming — is user-configurable from an on-screen Settings drawer, and the whole surface works from wall-mounted tablets down to phones.

Design principle: calm first. Nursery Mode is a nightlight that happens to log activities: dark-friendly colors, slow motion only where asked for, big touch targets (≥44px), and nothing that demands attention. The screen must be glanceable from across a dark room and operable one-handed while holding a baby.

This PRD replaces the existing Nursery Mode outright — no feature flag or side-by-side period.

2. Goals & Non-Goals

Goals

  • Log any of the four core activities in one tap from the nursery screen, with undo.
  • Four scenes (Ambient, Starlit, Tapestry, Photo) sharing one settings model; every scene usable as a genuine nightlight.
  • Deep personalization from artwork the team ships as greyscale assets: palettes recolor every sprite, wallpaper, and rug at runtime.
  • Layout independent of scene: glass activity Cards or icon-forward Big Tiles over any background.
  • Responsive: tablet-first (wall-mounted / bedside), fully functional on phone and desktop browsers.
  • Settings persist per user as a JSON string; a device picks up the signed-in user's configuration.

Non-Goals (v1)

  • Success-metric instrumentation (explicitly out of scope for this document).
  • Sound / white-noise features.
  • Editing activity history from Nursery Mode (undo of the just-logged entry only).
  • User-uploaded sprite artwork (users upload photos only; sprites are first-party assets).
  • Exit protection — Exit works with a single tap (no PIN / hold-to-exit).

3. User Stories

  • As a parent at 3am, I can glance at the screen and read the time and the last feed without picking up my phone.
  • As a parent finishing a diaper change, I tap Wet once and see a quiet confirmation with Undo — no forms.
  • As a parent of two, I tap the baby's name to switch which child the screen shows and logs against (existing behavior, unchanged).
  • As a design-conscious parent, I pick the Tapestry scene, a paisley rug or a pinstripe-and-teddy-bears arrangement, and tune it to my nursery's colors.
  • As a parent who built a nursery around a theme, I drop a photo of it behind the tiles and the icons tint to match.

4. Screen Anatomy

  • Top bar — ghost buttons: Settings (opens drawer) and Exit (returns to app, unprotected).
  • Clock block — large serif time (12/24h), italic baby name beside it (tap name to switch baby — existing switcher, unchanged), uppercase letter-spaced date below.
  • Activity area — Cards or Big Tiles layout (§6) for Feed, Pump, Diaper, Sleep; any activity can be toggled off in Settings.
  • Footer — "NURSERY MODE" wordmark + wake-lock status indicator.
  • Background — active scene (§5), always behind a legibility scrim; global Dim/Saturation filters apply to the background only, never the foreground text.

5. Scenes

5.1 Ambient

Animated gradient nightlight. Background picker offers:

  • Aurora — drifting blurred color blobs over a base gradient. Color range slider (0–100) scales the ± hue spread of the blobs from near-monochrome to full spectrum.
  • Waves — layered wave bank anchored to the bottom. Motion slider: 0 = still; otherwise the bank slowly rocks (rotates about its base) and drifts laterally; speed and amplitude scale together.
  • Bubbles — glassy orbs rise from the bottom edge with lateral drift and staggered timing. Sliders: count (4–80, default 24), min size, max size (px).
  • Sprite outlines — any of the 11 sprite sets rendered as faint line-art icons (edge-traced from the greyscale artwork, tinted to the scene hue, ~34% opacity). Sliders: Rotation (0 = upright → random tilt up to full tumble), Movement (0 = static collision-free arrangement; >0 = icons float freely across the screen in random directions, speed scales), Icon size (0 = uniform → wide small-to-large variance). Picker thumbnails show one random pose over the ambient gradient.

5.2 Starlit

  • Static starfield: each star has a fixed position and its own brightness (dim → bright). The brightest ~18% carry a soft glow and fire an occasional cross-shaped sparkle on independent random timers. No global pulsing.
  • Star density slider 30–400, default 200.
  • Aura toggle — pronounced aurora curtains rendered over the starfield (screen-blended, slow sway).

5.3 Tapestry

Composed wallpaper: a backdrop + scattered objects, all tinted by the palette (§7).

  • Backdrop (13 options): 8 CSS patterns drawn from the base color — Plain, Pinstripe, Horizontal, Diagonal, Chevron, Dots, Blocks, Scallops — plus 5 full-bleed recolored artworks: Classic / Trailing / Garden Paisley, Medallion / Heirloom Rug. Selecting a rug defaults both objects to None; returning to a CSS backdrop restores Teddy Bears + Stars if the user hasn't customized.
  • Primary object (None + 11 sets) and Accent object (None + 11 sets): Teddy Bears, Kittens, Puppies, Unicorns, Butterflies, Flowers, Rockets, Cars, Sports Balls, Stars, Fairies. Thumbnails show one random pose over the base color.
  • Placement algorithm — dart-throwing: candidates get a random position, pose, size (0.62×–1.3×), and rotation (±28°); any candidate whose bounding circle (+margin) intersects an already-placed object is rejected. ~17 primaries land first, then ~16 accents at 50% scale fill leftover pockets. Pose selection is weighted: each use multiplies that pose's weight by 0.4 so variety spreads evenly. Result: organic, never-overlapping texture; re-dealt per visit.

5.4 Photo

  • Personal photo as the background behind a legibility scrim. Sources: pick from the Photos gallery (existing feature) or upload directly in Settings.
  • Auto icon color: sample the photo's dominant color and derive a light, contrasting icon tint (production replaces the prototype's hue-derived approximation with true pixel sampling — downscale to ≤64px, cluster, pick dominant hue, output oklch tint at fixed lightness).

6. Layouts & Quick Logging

  • Cards — 2×2 glass cards (1-column on phone): icon badge, activity name, last-event time + detail (right-aligned serif), and action buttons: Feed → Bottle / Breast L / Breast R; Pump → Start Left / Right / Both; Diaper → Wet / Dirty / Both; Sleep → Start Sleep.
  • Big Tiles — icon-forward square tiles (badge, label, last-event time). Tap opens the same actions as a compact overlay.
  • One-tap logging with undo: tapping an action writes a real log entry immediately (timestamped now, attributed to the signed-in user and selected baby) and shows a quiet toast — "Wet diaper logged · Undo" — for 6s. Undo deletes the entry. Card/tile metadata refreshes instantly. Timers (Sleep, Pump) follow existing start/stop semantics: an active timer replaces the card's actions with elapsed time + Stop.
  • All hit targets ≥44px; buttons inherit the transparency setting; text always full-opacity.

8. Asset Pipeline & Recolor Engine

Asset change from prototype: the prototype auto-slices multi-sprite sheets (background flood-fill + connected-component detection). Production ships one SVG per sprite, removing the slicing step entirely. The recolor engine below is unchanged.
  • Source format: greyscale vector artwork (or greyscale PNG fallback), transparent or uniform background, one sprite per file. Suggested layout: assets/nursery/sprites/<set>/<pose>.svg + a manifest JSON per set (id, label, poses[], native aspect ratio).
  • Runtime canvas recolor (as prototyped): rasterize → map each grey tone by luminance onto the active palette — lightest ~20% → base color, darker bands → the 5 pattern colors in order — preserving tonal depth (output lightness = 0.55·grey + 0.45·target). SVG text fills (#hex and rgb()) can be remapped without rasterizing; rasters go through a 256-entry LUT. Background pixels → transparent.
  • Outline variant: edge-trace (silhouette + interior luminance edges, dilated ~5px at source scale), tinted to scene hue, exported as transparent PNG blob.
  • Caching: recolored results cached per (asset, palette) as object URLs; palette edits re-tint live. Rug artworks are large (~100–250KB SVG) — recolor lazily on first use.
  • Motion & accessibility: all animation behind prefers-reduced-motion; static fallbacks render full content.

10. Technical Notes

  • Wake lock: Screen Wake Lock API with visibility-change re-acquisition; status shown in footer. Fullscreen via Fullscreen API (user-initiated).
  • Clock: local time, minute precision display, seconds-level tick to keep minute rollover crisp.
  • Performance: scatter/outline fields are static DOM (no rAF loops); CSS animations only. Target: no dropped frames on a 2019-class tablet; recolor of the largest asset < 150ms off the interaction path.
  • Responsive: ≤680px — single-column cards, 2-up tiles, full-width settings drawer, fixed background with scrolling foreground; clock scales via viewport-clamped type.
  • Data: last-event metadata and quick-log writes use existing activity endpoints; no new API surface beyond the user-preference JSON.
