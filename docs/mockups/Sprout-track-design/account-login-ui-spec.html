Account & Login — Reskin UI Spec

Product: Sprout Track (PWA + marketing site)  ·  Scope: Login flow, account dropdown, account manager & sub-forms  ·  Version: 1.0 Draft  ·  Date: Jul 17, 2026  ·  Owner: John Overton

Prototype: v1-storybook/account.html  ·  Theme reference: V1 Storybook landing (v1-storybook/style.css, v1-storybook/account.css)

1. Overview & scope

This is a reskin-only specification. All functionality of the current account system stays exactly as it is — same fields, same validation rules, same endpoints, same states, same flows. What changes is the presentation layer: the bright-white modal system is replaced with the V1 "storybook" theme used across the marketing overhaul — paper-cream surfaces, Literata/Alegreya Sans type, teal + apricot accents, hand-drawn duotone sprites, and a consistent 1.8px-stroke icon set.

Non-goals: no new fields, no renamed API contracts, no changes to auth logic, session handling, subscription/billing behavior, or role permissions. Copy changes are cosmetic (voice only) and must not alter the meaning of any label a support doc references.

3.3 Shape, depth, spacing

  • Radii: pane corners (modal fallback) 16px · dropdown 14px · buttons 12px (small 9px) · inputs 10px · chips pill.
  • Shadows are warm, never gray: drawer -30px 0 70px -30px rgba(30,25,10,.4); dropdown 0 22px 48px -20px rgba(58,48,24,.45). No colored glows.
  • Pane padding: 24–28px horizontal; footer bar 15px vertical; sections 22px vertical.
  • No nested cards. Sections separate with 1px dashed --line rules; rows within a section use solid hairlines #e8ddc2.

4. Surfaces & motion

  • Drawer: fixed right, full height, width: min(520px, 100vw), 1px --line left border. Enter: slide from +48px with fade, 250ms ease. Auth drawers use the same surface.
  • Backdrop: ink scrim rgba(28,42,34,.44). Click outside closes the top pane; Esc does the same.
  • Sub-forms (baby, caretaker, contact, reset-from-settings) open stacked in the same drawer with a back arrow at the header's left; Back/Cancel returns to the account manager without losing tab state.
  • Toast: confirmation pill bottom-center, --ink background, cream text, pill radius, ~3.4s, 250ms rise-in. Used for saves, sends, sign-out.
  • Respect prefers-reduced-motion: disable slide/drop animations, keep instant show/hide.

6. Account manager (drawer)

  • Header: title "Your account" only — no subtitle sentence. Close (×) icon button top-right. The footer "Close" button from the current design is removed (redundant with ×).
  • Tabs: "Account" / "Family & people" — text tabs with a 2.5px teal underline on the active tab; no mint pill fill, no tab icons.

6.3 Family & people tab

  • Rows, not cards: name (Literata) + chips + one metadata line, "Edit" as a teal text link right-aligned. Hairline between rows.
  • Section headers carry a 20px teal icon + "Add …" ghost button with a plus icon.
  • Chips (12px, 700, pill): AdminUserOwnerBoyInactive — sentence case, never ALL-CAPS ("MALE" → "Boy"). Active state is implied; only Inactive gets a chip.
  • Baby metadata line folds in the warning times: "1 year 8 months · feed nudge 3h · diaper nudge 2h".
  • Contacts empty state: 30px muted phone icon, Literata "No contacts yet", one warm sentence. No dashed placeholder box.

7. Forms (all sub-forms + auth)

  • Inputs: --card fill, 1.5px --line border, 10px radius, 10×13px padding, 16px ink text. Placeholder #a89d82.
  • Focus: teal border + 3px soft ring rgba(12,107,98,.14). Replaces the current blue/green glow.
  • Labels: above the field, Alegreya Sans 700 @14.5px ink. Optionality is written in the label — "Phone (optional)" — no red asterisks.
  • Helper text: 13px --sub below the field (e.g. "Admins can edit family settings and people.").
  • Field groups: related fields (sign-in credentials, reminder times) sit under a dashed top rule with a Literata group title + one-line explainer (e.g. "How they sign in — a 2-digit ID and a PIN").
  • Password checklist (sign-up): the 5 existing rules in a compact two-column 13px list; circles fill teal with a check as each rule passes. Same rules, same enforcement.
  • Footer bar: sub-forms end in a sticky footer (--paper2, top rule): ghost Cancel + primary teal submit, right-aligned. Auth drawers use a full-width primary button inside the body instead.
  • Two-column rows for paired fields (first/last name, feed/diaper time, phone/email); collapse to one column ≤640px.

9. Iconography & sprites

  • Icons: single hand-set SVG sprite, 24px grid, 1.8px stroke, round caps/joins, currentColor. Set: user, mail, key, gear, chat, house, log-out, plus, phone, download, baby face, people, shield, check, chevron, back arrow, ×, alert triangle. This replaces Lucide defaults so weights match the marketing site.
  • Sprites (duotone art from v1-storybook/art/): butterfly (~42px, rotated ~9°) beside the account-drawer close button; star (~38px) on Create account. Decorative only (aria-hidden, pointer-events:none), hidden ≤640px, and removable via a single body attribute.

10. Copy voice

  • Short, warm, specific; sentence case everywhere (headings, buttons, chips).
  • Buttons are first-person where it fits: "Sign me in", "Start my free trial", "Download my data".
  • Reassure at moments of anxiety: expired ("your data is safe"), close account ("Download your data first"), reset ("works for one hour").
  • No exclamation marks, no "Oops!", no emoji.

11. Responsive & accessibility

  • ≤640px: drawers go full-width; paired fields stack; sprites hide; pane padding tightens to 18px.
  • Touch targets ≥44px (buttons, menu items, tabs, ×).
  • Focus states visible on every interactive element (teal ring); drawer traps focus; Esc closes; × carries an aria-label.
  • Contrast: body text and labels on paper meet WCAG AA; --sub is reserved for non-essential helper text.
Out of scope reminder: if any current behavior conflicts with a visual described here (e.g. a validation message's trigger), the behavior wins — flag it rather than changing logic.
