Capacitor Mobile Shell — Punch List

Product: Sprout Track (Capacitor iOS/Android shell)  ·  Scope: everything designed in the interactive mockup, for implementation against the real codebase  ·  Version: 1.0  ·  Date: Jul 21, 2026  ·  Owner: John Overton

1. Context

The shell is a native Capacitor wrapper around the existing Sprout Track web app. The native layer owns: launch/splash, sign-in fork, credential storage (secure keychain), the saved-families list, the setup wizard for new account users, settings, offline states, and biometric unlock. Once a family is opened, the shell hands off to the web app in a webview; the web app owns everything inside except a handful of app-adapted behaviors listed in §8.

All visual styling follows the v1 storybook theme (paper cream #f7f1e2, ink #26382f, teal #0c6b62, apricot #c2691e, Literata display + Alegreya Sans body, dashed dividers, plush art sprites). Copy voice is warm and non-technical throughout ("Knocking on the door…", "Planting your sprout…").

2. Launch & splash P0

  • Full-screen splash: lifestyle hero photo (same asset as v1 landing hero) with the cream radial + linear gradient overlaid, slow Ken Burns zoom-out (~6.5s ease-out, scale 1.09 → 1).
  • Centered circle badge logo (no drop shadow, no ring — image as-is), pop-in animation (scale .6 → 1, slight overshoot), then "Sprout Track" wordmark (Literata 33px) and kicker "THE SHAREABLE BABY TRACKER" (apricot, letterspaced caps) rising in staggered (~280ms / ~500ms delays).
  • Exit: after ~2.1s the whole splash fades out (~550ms) while content drifts up 16px, revealing the next screen.
  • Routing after splash: no saved families → sign-in fork; saved families → My Families; saved families + auto-open enabled → straight into connecting to the starred family (biometric prompt fires over the list).

3. Sign-in fork (front screen) P0

  • Top ~176px: same hero photo + cream gradient fading into paper; circle badge logo overlapping the fold.
  • Headline "Everyone you love, on the same page." + "How do you sign in to your family?"
  • Two choice cards:
    1. With my Sprout Track account — "Email & password. New here? This creates your account too." → account sign-in (§4).
    2. Family link shared with you? — "Sign in here with the family link and your family PIN or personal caretaker PIN." → caretaker flow (§6). Do not mention "hosted/self-hosted" here.
  • Footnote: "Either way, your sign-in stays in this phone's secure keychain."
  • "Add a family" from My Families returns to this fork screen (both routes always reachable).

4. Sprout Track account flow P0

Sign in

  • Email + password against sprout-track.com account auth.
  • "Unlock with Face ID / Touch ID next time" checkbox (default on) — stores the credential in the keychain (§9).
  • Error states: wrong email/password ("That email and password didn't match…"), rate-limited/lockout ("Too many tries - the server is taking a breather…"), unreachable.
  • Links: "New here? Start your free trial" → create account; "Forgot your password? Reset it" → reset.

Create account

  • First name, last name, email, password with live requirements checklist (8+ chars, number, lowercase, symbol, uppercase — pill turns teal per rule met). Button disabled until all pass.
  • Terms/Privacy legal line; "Already have an account? Sign in."
  • On success: account has no family → setup wizard (§5).

Reset password

  • Email field → "Email me the link" → toast "Reset link sent to {email} - it works for one hour." and return to sign-in.

Post-auth routing

  • Sign-in where the account already has a family → save that family to the device list and land on My Families.
  • Sign-in where the account has no family (or fresh sign-up) → setup wizard.

5. Setup wizard (3 steps, in-app, themed) P0

Mirrors src/components/SetupWizard behavior; header has logo + wordmark, teal progress bar, "STEP n OF 3", storybook art sprite per step. Commit-as-you-go: each Next persists to the server (family → security → baby); once a stage is saved there is no Back to it — steps 2/3 instead show a "✓ Family saved" / "✓ Security saved" check by the step counter. Resume lands the user on their lowest unsaved stage.

Step 1 — Create your family

  • Family name; family link (slug) auto-generated from name until manually touched; regenerate button suggests {base}-{3 digits}.
  • Live URL preview: "Your family will live at sprout-track.com/{slug}".
  • Debounced (~500ms) availability check with three states: checking ("Checking if that link is free…"), available (teal check, "/{slug} is free - it's yours."), error box.
  • Validation mirrors app/api/utils/slug-validation.ts: lowercase/numbers/hyphens only, 3–50 chars, reserved-URL list (account, api, coming-soon, family-manager, family-select, setup, sphome, login, auth, context, globals, layout, metadata, page, template, features, home, pricing, privacy, terms, health, logs, maintenance, status, update, uptime, version), plus server-side taken check. Spaces typed into the field auto-hyphenate.

Step 2 — Security ("Who can open the book?")

  • Radio cards: One shared family PIN (PIN + confirm, 6–10 digits, digits-only input) vs Caretakers with their own PINs (default).
  • Caretaker form: 2-digit login ID with live validation (digits only; 00 reserved; duplicate check), name, PIN (6–10 digits, stripped to digits), optional type. First caretaker is forced Admin; for account users it is prefilled as their profile (name from account, type "Account Owner", CTA "Create my profile"). Subsequent caretakers get a Role select (User default / Admin).
  • Added caretakers listed as rows (name, role chip, type chip, ID, remove). Next requires PIN valid+matching or ≥1 caretaker.
  • Account users: link the account to its caretaker (system caretaker for shared-PIN mode, first caretaker otherwise) per existing wizard logic.

Step 3 — Add your baby

  • First name, last name, birth date, gender — all required.
  • "Gentle nudges": feed warning (default 02:00) and diaper warning (default 03:00), hh:mm validated inline.
  • Feed timer counts from (start/end of feeding); feed-type checkboxes (breast feeds, breast-milk bottles, formula bottles, other bottles, food — all default checked; all-checked persists as null).
  • Complete Setup → busy "Planting your sprout…" → family saved to device (starred if first) → My Families with welcome toast. Refresh the auth token so it carries family info (account auth).

6. Caretaker / family-link flow P0

  • Single "family link" field (e.g. myhost.com/smith-family) — works for hosted and self-hosted servers.
  • "Find my family" resolves the server + slug: errors for malformed address, missing slug, family not found, not a Sprout server, unreachable.
  • Found family renders as a card (avatar initial, name, host, Hosted/Self-hosted chip). Plain-http addresses get an unencrypted-connection warning (allowed, warned).
  • Credential entry adapts to the family's auth type: login ID + PIN, or family PIN only.
  • Biometric-save checkbox; "Verify & save" validates against the server before storing; wrong-PIN and lockout errors surfaced inline.

7. My Families, settings, offline, unlock P0

My Families

  • Card per saved family: avatar initial (teal = hosted, apricot = self-hosted), name, host + last-opened, Face ID glyph when biometric unlock is enabled, "Opens first" chip on the starred family.
  • Row actions: star (sets the auto-open default — exactly one starred), remove (removes family + its keychain entry). Dashed "Add a family" → fork screen.
  • Header: title + settings gear (use a real gear icon, not a sun/rays glyph).
  • Tapping a family: biometric prompt (if enabled) → connecting screen ("Opening {family}… signing you in with your saved credentials") → webview.

Settings

  • "Open my starred family automatically" toggle — copy explicitly ties auto-open to the ★ family by name.
  • Keychain explainer section ("Your sign-ins stay put").
  • "Clear this phone" with inline confirm — wipes all saved families + keychain entries, server data untouched; returns to fork screen.
  • Version footer: "Sprout Track Mobile v0.1.0 / The tracker itself lives on your server."

Offline / errors

  • Server unreachable on open → themed offline screen (kitten art): "Can't reach your server." + Try again / Switch family.

Biometric unlock

  • Native Face ID / Touch ID sheet before auto-fill of saved credentials; success state ("Unlocked") then connect. Both biometric types supported.

8. Webview integration P1

  • Side menu (hamburger): standard web nav (Log Entry, Full Log, Calendar, Reports, Nursery Mode), version/language line, Settings — and a single "Exit to My Families" item replacing both "Switch Family" and "Logout" when running inside the shell. It returns to the native family list. No separate Account item in the sidebar.
  • Header "Hi, {name} ⌄" pop-down (account users only, as on web): name + email, Account settings, Send feedback, Log out (Log out inside the shell also exits to My Families).
  • Account settings drawer: same as v1 web overhaul (Account / Family & people tabs, edit name/email, reset password, family info, babies, caretakers) except the subscription section when in-app:
    • Show status only (Active/Trial/Expired + renewal date + price).
    • Note: "Subscriptions are managed on the web, not in this app."
    • Button "Manage your subscription at sprout-track.com" (external-link icon) → opens the system browser (Capacitor Browser plugin), never Stripe inside the webview. This is the Apple/Google payments compliance boundary — no Renew/Payment-history/Stripe links rendered in-app.
  • The web app detects it's inside the shell (user-agent flag or query param injected by the shell) to swap these behaviors.

9. Credential & state storage P0

  • Per-family credential (PIN, ID+PIN, or account email/password token) in the platform secure keychain; never synced off-device; deleted with the family.
  • Device store: saved families (name, host, slug, hosted flag, biometric flag, starred flag, last-opened), auto-open setting.
  • Biometric gate wraps keychain retrieval; declining biometrics falls back to manual entry.

10. App icons P2

  • Home-screen icon: the square sprout mark (cream bg, orange ground bar) — assets at 192/512/1024 (uploads/sprout-track-square-*.png); OS applies its own mask (iOS squircle, Android circle).
  • In-app branding keeps the existing circle badge logo, rendered without added drop shadows or rings.

12. Anti-slop design pass (required before merge)

Run a final review against the anti-“AI slop” reference (uploads/compass_artifact_wf-235148cc-397a-4eb5-ab59-bf4306e1ff65_text_markdown.md). The shell must read as Sprout Track's storybook world, not a generic AI-generated app. Concretely:

Locked design tokens (use exactly these — no invented values)

  • Palette: paper #f7f1e2, paper-2 #efe6d0, card #fffdf6, ink #26382f, body #3d5044, sub #6b7a6c, line #ddd2b8, teal #0c6b62 / deep #0a544d, apricot #c2691e, rust #9e2b25. Dominant cream, teal for action, apricot as the sharp accent. Extend via tints only; never introduce new hues.
  • Type: Literata (display/headings) + Alegreya Sans (body/UI). Nothing else — no Inter, Roboto, Space Grotesk, or system-font fallthrough on the shell's own screens.
  • Shape: the existing radius scale (~9–16px, pills only for chips/toggles), dashed 1px dividers, soft warm shadows (rgba(58,48,24,…)) — never colored glows.

Do-not-use list (the slop tells)

  • No purple/indigo/blue gradient accents; no gradient meshes, floating blobs, or aurora backgrounds — the only photographic background is the landing-hero photo with the cream gradient (splash + fork top).
  • No glassmorphism/frosted cards (the one exception: the OS-native biometric sheet, which intentionally mimics the system surface).
  • No colored left/top border strips on cards or callouts; no cards nested in cards.
  • No eyebrow badge pills above headings other than the established apricot kicker style; no emoji in UI; no all-caps body text.
  • No unmodified component-library defaults (shadcn etc.) — every control is hand-styled to the tokens above.
  • No dark mode unless designed deliberately later; webview dark handling belongs to the web app.
  • Copy: no “Supercharge/Unlock/Seamlessly” filler and no em dashes — keep the warm, specific voice from the copy inventory (§11). Errors talk like a person, not a status code.

Pass criteria

  • 5-second test on each screen: a new user can say what it is and what to tap.
  • Side-by-side with capacitor-app.html: spacing, type scale, and color match the mockup, not a framework default.
  • Optional: run Krebs's open-source ai-design-checker against the built screens; investigate anything it flags.
For the implementing agent: the mockup (capacitor-app.html + capacitor-screens.jsx, capacitor-wizard.jsx, capacitor-app.jsx) is the source of truth for layout, spacing, states, and copy. Its tweaks panel enumerates the scenario matrix to test: caretaker sign-in type (ID+PIN / PIN), find-family results, credential errors (wrong / locked), account-has-family, server reachability, Face vs Touch ID, first-run vs returning user.
